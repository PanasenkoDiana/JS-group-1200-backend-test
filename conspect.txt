Архитектура проекта - разделение ответственности и отделения логики приложения от внешних деталей
1. Проще читать код
2. Изменения локализируются
3. Сервис проще тестировать отдельно от express
4. Проще добавлять новые endpoint-ы
5. Одна функция не пытается одновременно маршрутизировать, валидировать, искать данные и формировать ответ

Существует 4 слоя
1. Роутер - знает http метод и url, передает значение нужному handler-у
2. handler - получает req, res, читает query параметры и body, 
проверяет формат входных http данных, после чего вызывает сервис
3. Сервис - получает обычные значения или объекты, здесь находятся правила приложения
4. Репозиторий - работает с базой данных

Для того что бы использовать импорт и экспорт в файле package.json, нужно заменить type на "type": "module",

type script - это язык програмирование разширяющий java script системой типов, 
все файлы тайп скрипта имеют разширение .ts 

npx tsc --init - создает файл конфигурации тайп скрипта
npx - это инструмент системы node js который позволяет запускать пакеты и их команды
tsc - это тайп скрипт компилятор
--init - это параметр для tsc

npx tsc --noEmit - проверяет код тайп скрипта без компиляции и без создание доп. файлов
тип any -- позволяет выключить типизацию. 
Используется только в том случае, если невозможно 
определить более точный тип

dto - Data Transfer Object описывает структуру данных передаваемых пользователем

Зависимость -- это то, что нужно одному объекту или модулю для выполнения его работы
DI (Dependency Injection) -- это подход при котором объект не создает свои зависимости самостоятельно, 
а получает их из вне в проекте будем использовать ручной DI через параметры фабричных функций.
DIP (Dependency Inversion Principle) -- архетиктурный принцип: высокоуровневая бизнес логика не должна 
зависить от низкоуровневых деталей
Compоsition root -- это место где приложения создаёт конкретные реализации, и связывает их между собой

база данних це організоване сховище інформації 
інформація зберігается окремо від додатку
СУБД - система управління базою данних
вона приймає запити, зберігає запити, перевіряє обмеження, повертає данні, та видаляє 
CRUD - це чотири основні операції які можна виконувати з данними 
С - create, R - read, U - Upgrade, D - Delete
postgreSQL виконує SQL запити 
SQL - Struсtured, query, Language - це мова за допомогою якої ми 
надсилаємо команди до бази данних
ORM - Object, Relational, Mapping - Це шар між кодом та базою данних

 node -v - перевіряє версію ноди

 npx prisma@latest orm init --yes --target postgres --authoring pls --write-env
 Команда для ініціалізації prisma
 prisma@latest - запускає останню версію прізми
 orm init - ініціалізує прізму в проект
 --yes - автоматично відповідає на всі питання
 --target postgres - говорить призмі що база данних буде postgreSQL
 --authoring pls - використовує Prisma Schema Language (PLS), тобто
 звичний формат для прізми .prisma
 --write-env - створює .env на основі .env-example 

 npx prisma --version - виводить версію прізми
 npx create-db@latest - команда для створення тимчасової бази данних

 npx prisma db init -- створює таблиці в пустій базі данних. Виконуємо тільки після emit
 npx prisma db update -- дозволяє оновити db
 npx prisma db sign --db -- підписує бд за посиланням
 npx prisma db verify -- перевірка співпадіння і валідності схеми
